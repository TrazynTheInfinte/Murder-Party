# Mask naming uses a hardcoded friend-roster dispatch, not self-service registration

The Mask needs a victim's exact Minecraft username written into its NBT as a proper JSON text component — the one field the ID Mask mod actually reads to resolve identity. 1.20.1 has no macros (ADR 0004), so there's no way to take a runtime-only-known string and inject it into NBT directly; extensive live testing also ruled out every indirect route (copying a plain string field, live-resolving `nbt`/`selector` text components — the mod reads `display.Name` through its own logic, not Minecraft's live-resolving renderer).

The fix: since this runs on a closed friend-group server with a small, stable, known roster rather than the general public, a dedicated small function is pre-written for each known friend's exact username as a literal string, selected at Strike time by checking "is the victim this exact name" per candidate — the same bounded-dispatch pattern already used for the 10 vote slots. A more "automatic" alternative was considered and rejected: a persistent-storage self-service registration system, where players could register themselves via an in-game command without ever touching datapack files. That was ruled out as meaningfully more moving parts (index allocation, a growing NBT list, a wider dispatch range) for a convenience that doesn't matter much given how rarely this friend group's roster actually changes. Adding a new friend later means adding one more small file and a `/reload` — a deliberately accepted ongoing cost in exchange for the simpler system now.
